# HTML → DOCX 转换逻辑与架构

本文档描述 `packages/html2docx` 中实现的转换逻辑。它不是严格按属性逐条对照 HTML 规范到 OOXML 规范的翻译器，而是基于"真实浏览器渲染 + 文档意图识别 + 原生 Word 重建"的混合转换器。

## 1. 目标与基本原则

转换器的目标是：

1. 在 Linux 或 macOS 上运行，不依赖 Microsoft Word。
2. 正文、标题、列表、表格、表单尽量保持可编辑。
3. 版式和视觉效果尽量接近 Chromium 渲染的 HTML。
4. Word 不擅长的效果使用局部截图，而不是整页栅格化。
5. 转换器保持独立，不修改现有业务代码。

当前最重要的设计原则是"结构优先，视觉兜底其次"：

- 能可靠映射到 Word 的内容，生成原生 OOXML。
- 渐变、复杂 SVG、徽章、纯装饰等无法可靠映射的，渲染为局部图片。
- 页面背景、绝对定位装饰，生成为不进入正文流的浮动图片。
- 不使用 PDF 中间格式，避免丢失语义、文本结构和可编辑性。

## 2. 整体流水线

```text
HTML 文件或 URL
    │
    ▼
无头 Chromium 加载页面
    │
    ├─ 等待网络资源和 Web 字体
    ├─ 检测 HTML 的设计宽度
    └─ 按设计宽度重新渲染
    │
    ▼
读取 DOM、计算样式和真实几何尺寸
    │
    ▼
识别文档结构，生成中间表示（IR）
    │
    ├─ 可编辑结构：段落、标题、列表、表格、卡片、表单
    └─ 图片兜底：渐变、SVG、徽章、页面装饰、背景
    │
    ▼
按 IR 收集需要截图的 DOM 元素
    │
    ▼
用 docx 库生成原生 OOXML
    │
    ▼
DOCX
    │
    ▼
Microsoft Word 导出 PDF/PNG，与 HTML 截图对比做回归
```

代码职责：

- `tools/cli.ts`：命令行入口（基于本地 Chrome 的 Playwright 驱动）。
- `src/convert.ts`：编排浏览器加载、IR 提取、截图收集和生成流程。
- `src/extract.ts`：浏览器提取函数的轻量组装入口。
- `src/browser/core/`：样式、文本、列表、布局、分类器等共享作用域的提取模块。
- `src/browser/`：表格、页面、表单媒体、视觉兜底等独立浏览器模块。
- `src/generate.ts`：DOCX 生成流程的轻量编排入口。
- `src/generate/`：页面设置、渲染上下文、Word 样式、流式节点、表格渲染等模块。

由于浏览器提取层需要经 `page.evaluate` 序列化为单个自包含函数，`src/browser/core/` 使用按职责拆分的函数体片段，由 `extract.ts` 在 Node 侧按固定顺序组装。外围独立能力通过 `page.addScriptTag` 注入，而不是把所有实现塞回单个文件。

## 3. 浏览器渲染阶段

### 3.1 Chrome 选择

`convert.ts` 按以下顺序查找浏览器：

1. `CHROME_PATH` 环境变量
2. macOS 上的 Google Chrome
3. Linux 上常见的 Google Chrome / Chromium 路径

该包通过 `BrowserDriver` 接口（`src/driver.ts`）与浏览器通信；CLI 和测试使用基于本地已安装 Chrome 的 Playwright 实现，应用使用 Electron 自带的 webContents。不下载 Chromium。部署到 Linux 时，必须在镜像中安装 Chromium，或设置 `CHROME_PATH`。

### 3.2 初始 A4 视口

初始视口为：

```text
794 × 1123 CSS px
```

这是 A4 在 96 DPI 下的近似尺寸。`deviceScaleFactor` 设为 2，以提高局部截图的清晰度。

### 3.3 设计宽度检测

许多 AI 生成的文档使用：

```css
body {
  max-width: 880px;
}
```

如果直接在 794px 宽的视口中提取，会产生额外换行，表格行高也会被放大。当前逻辑读取 `body` 的计算 `max-width`：

- 如果设计宽度大于初始 A4 视口；
- 且不超过 1600px；
- 则使用不小于 1024px 的设计视口重新加载页面。

这样提取到的换行和行高反映的是作者设计的尺寸，而不是事先被过窄视口挤压的结果。

如果流式文档在浏览器中约为 0.96–1.22 个页面高度（按设计画布宽度换算为 A4 比例），则视为具有单页设计意图，`pageFitSqueeze` 会对几何尺寸和字体做轻微的全文档压缩，避免 Word 略松的排版把最后一块内容（发票印章、页脚备注）挤到第二页。表格较多的文档享受不到"Word 排版更紧凑"的好处，因此超过 1.05 页时不应用压缩折扣。生成 OOXML 时，原生字号、间距、内边距、行高和边框再按 `目标页宽 / 设计视口宽` 缩放；局部截图按比例缩放到目标内容区宽度。

### 3.4 等待资源

页面加载期间：

- 优先等待 `networkidle0`；
- 超时后仍继续转换，避免外部资源阻塞整个任务；
- 等待 `document.fonts.ready`；
- 再等待短暂稳定期，让布局和字体完成重排。

无法访问的图片在提取时被识别为损坏并丢弃。

## 4. 提取层：DOM 与计算样式

由 `extract.ts` 组装的 `extractIR` 函数注入浏览器页面并在其中执行，因此可以直接访问：

- DOM 节点；
- `getComputedStyle`；
- `getBoundingClientRect`；
- `::before` / `::after` 伪元素；
- 图片加载状态；
- 文本节点的真实坐标。

提取的内容分为四类。

### 4.1 文本 run

文本不是仅按 DOM 标签粗略处理，而是转换为带样式的 run。目前支持：

- 字体族和字号；
- 粗体、斜体、下划线、删除线；
- 字体颜色；
- 行内背景色；
- 字间距；
- 上标、下标；
- `text-transform: uppercase`；
- 超链接；
- 换行（包括 `white-space: pre-wrap/pre-line` 文本中按行拆分的作者换行）；
- 小型行内图片；
- 宽空格产生的列位置和制表位。

连续文本节点和行内元素合并为单个段落，避免每个 `<span>` 都产生独立段落。

### 4.2 段落样式

段落级样式包括：

- 左对齐、居中、右对齐、两端对齐；
- 段前/段后间距；
- 行高比例；
- 左缩进；
- 背景色；
- 左边框和下边框；
- 单行色条的精确高度；
- 中日韩和拉丁文本标记。

转换器区分英文和中日韩的 Word 字体行距：

- 拉丁行距使用较小的补偿；
- 中日韩行距使用较大的补偿；
- 单行背景标题条使用精确行高，防止 Word 把色条拉高。

### 4.3 几何信息

结构节点存储浏览器测量的尺寸，例如：

- 表格列宽；
- 表格行高；
- flex/grid 子元素宽度；
- 卡片内边距；
- 块级外边距；
- 图片宽/高；
- 绝对定位元素坐标；
- 页面内容区宽/高；
- body 四边外边距。

这些数据用于抑制 Word 的自动适应和默认段落行距。

### 4.4 页面设置

提取后生成 `docsettings` 节点，存储 body 的实际四边外边距：

```js
{
  type: 'docsettings',
  marginsPx: {
    top,
    bottom,
    left,
    right,
  },
}
```

DOCX 不再统一使用固定的 2cm 上下页边距，而是尽量使用 HTML 的实际页面内边距。这解决了"内容尺寸正确，但最后一个表单框被固定页边距挤到第二页"的问题。

## 5. 意图识别层：DOM → IR

IR 是浏览器结构与 Word 结构之间的中间表示。它主动丢弃不重要的 HTML 实现细节，只保留生成 Word 输出所需的文档意图。

当前主要节点类型：

| IR 类型       | 含义                                 | Word 输出                          |
| ------------- | ------------------------------------ | ---------------------------------- |
| `docsettings` | 页边距                               | 节页边距                           |
| `heading`     | 标题                                 | 标题段落                           |
| `para`        | 普通段落                             | 段落 + TextRun                     |
| `list`        | 有序/无序列表                        | 原生 Word 编号                     |
| `table`       | HTML/CSS Grid 表格                   | 固定布局 Word 表格                 |
| `card`        | 带背景、边框、内边距的卡片           | 单单元格表格                       |
| `kpirow`      | flex/grid 水平布局                   | 单行多列表格                       |
| `formfield`   | 输入框、文本域、下拉框               | 带下划线的段落或单单元格表格       |
| `code`        | 多行等宽文本                         | 等宽底纹段落                       |
| `image`       | 普通图片或局部截图                   | 行内 ImageRun                      |
| `floatimg`    | 页面装饰、签名、页脚                 | 浮动 ImageRun                      |
| `pagebg`      | 页面背景                             | 页面后方的浮动图片/背景色          |
| `pagebreak`   | 强制分页                             | PageBreak                          |
| `hr`          | 水平线或伪元素色条                   | 段落下边框                         |
| `spacer`      | 大段垂直空白                         | 精确高度的空段落                   |

### 5.1 分类顺序

分类顺序非常重要。`processElement` 目前大致按以下优先级处理：

1. 跳过不可见元素和 `script/style` 等无关标签。
2. 识别页面底部的大签名。
3. 识别绝对定位或固定装饰。
4. 提取分页和页面顶部的大段空白。
5. 处理原生语义标签：
   - 标题；
   - HTML 表格；
   - 列表；
   - 代码；
   - HR；
   - 图片；
   - 表单。
6. 处理 SVG、canvas、checkbox/radio。
7. 识别徽章、胶囊、装饰叶片和渐变容器。
8. 识别 CSS Grid 表格。
9. 识别页面级多列布局。
10. 识别多行、结构一致的 grid/flex 布局。
11. 识别单行 flex/grid 布局。
12. 识别卡片。
13. 回退为普通段落并递归子节点。

高保真规则必须先于通用块级递归；否则复杂组件会被过早拆成普通段落。

## 6. 主要结构识别逻辑

### 6.1 HTML 表格

原生 `<table>` 提取以下内容：

- 每列的测量宽度；
- 每行的测量高度；
- colspan；
- 单元格内边距；
- 四边边框；
- 背景色；
- 水平和垂直对齐；
- 表头行；
- 单元格内的段落或嵌套结构。

生成时：

- 使用固定表格布局；
- 写入表格网格列宽；
- 同时写入单元格宽度；
- 按 colspan 合并相邻网格宽度；
- 行高使用浏览器测量值；
- 需要严格保真时使用 `HeightRule.EXACT`。

同时设置表格网格和单元格宽度，是为了阻止 Word 的自动适应按文本长度重新分配列宽。

### 6.2 CSS Grid 表格

如果容器包含多行结构一致的 Grid：

- 每行可见子项数量相同；
- 列数在合理范围内；
- 各行宽度彼此接近；
- 行数足够多或有明显外边框；

则转换为 `table`，而不是一组独立文本块。

这用于问卷、课程表、调查表等不使用 `<table>` 的模板。

### 6.3 Flex/Grid 水平行

并排的 KPI、个人信息栏、标签行、页头等转换为 `kpirow`：

- 列宽由子元素的真实边界和间隙中点计算；
- 检测每个子元素在其对应列中的左/中/右位置；
- 存储父容器的行高和内边距；
- 在 Word 侧生成固定布局的单行多列表格。

子元素高度的默认上限为 500px（超过则视为页面级两列布局）；但列数 ≥3 且宽度相近的高卡片行（定价方案）放宽到 950px——Word 页面仍能容纳这样一行，从而保留并排结构。

如果容器左侧有绝对定位色块：

- 色块单独成为第一列；
- 正文内容成为第二列；
- 色块宽度使用浏览器测量值；
- 修正原本相对整个容器的正文左缩进。

服务评价页面的页头色块就是这样处理的。

### 6.4 卡片

带背景、边框、左侧强调线或明显内边距的块识别为 `card`。

卡片输出为单单元格 Word 表格，保留：

- 背景色；
- 完整边框；
- 左或上强调边框；
- 四边内边距；
- 上下外边距；
- 可编辑的内部内容。

使用表格而非段落底纹，是因为 Word 的段落底纹无法可靠表达四边内边距和完整卡片边框。

**扁平化**：浅色顶层卡片（整页区块）若高于半页且允许跨页，无法用单行表格表达——Word 嵌套表格不能跨页——因此扁平化为顺序段落流。扁平化时，卡片的底纹传播到所有子块：para/heading 的段落底纹、spacer 段落、列表项、kpirow 单元格和间隙、表格单元格；每个子块自身的段前/段后间距用 `ambientShading` 标记为周围区块的背景色，避免露出页面背景形成条纹。

### 6.5 页面级两列

简历等页面级两列布局输出为：

- 单行两列；
- 无边框 Word 表格；
- 每列完整放入对应单元格；
- 表格行允许跨页；
- 保留列背景和内边距。

不按 Y 坐标把页面切成大量小行，因为一旦 Word 分页，这种做法容易出现左右列错位。

列内段落和卡片间距适度压缩，以减少 HTML 与 Word 分页引擎差异导致的额外页数。

### 6.6 表单

目前不生成真正的 Word 内容控件，而是生成视觉上可编辑的表单：

- 只有下边框的输入框 → 带下边框的段落；
- 带框输入框、文本域、下拉框 → 单单元格表格；
- 保留宽/高、边框、背景、内边距和已有文本；
- checkbox/radio → Unicode 方框或圆圈字符。

这种方式兼容性高，但缺少真正 Word 表单控件的校验和字段属性。

### 6.7 列表

支持两种来源：

1. 原生 `<ul>` / `<ol>`；
2. Word 导出的伪列表，例如 Symbol 字体的"·""•""▪"等字符。

对伪列表，从文本中剥离假项目符号并转换为原生 Word 编号，避免重复圆点。

### 6.8 水平线和伪元素

`<hr>` 和符合条件的 `::before` / `::after` 色条提取以下内容：

- 宽度比例；
- 高度；
- 颜色；
- 左对齐或居中。

在 Word 侧用带缩进的段落下边框重建。

## 7. 图片兜底策略

### 7.1 为什么不全部截图

整页截图静态视觉一致性最高，但会导致：

- 文本无法编辑；
- 无法搜索和复制；
- 文件体积大；
- 无法正常分页；
- 不适合作为 DOCX。

因此目前只对 Word 难以表达的局部区域截图。

### 7.2 会被截图的内容

主要包括：

- 普通 `<img>`；
- SVG 和 canvas；
- 渐变背景容器；
- 圆角胶囊和复杂徽章；
- 小型装饰形状；
- 无文本、字形在 `::before/::after` 中的图标字体元素；
- 复杂徽章网格；
- 页面背景图；
- 绝对定位装饰；
- 过大的底部签名。

待截图元素会被赋予唯一的 `data-h2d-id`。`convert.ts` 遍历 IR 收集这些 ID，再通过 Puppeteer 对相应 DOM 元素截图。

### 7.3 页面背景

页面背景复制到离屏背景层：

- 保留背景色、图片、尺寸、位置和重复模式；
- 支持 body/html 背景；
- 支持简单的 `::before` 背景叠加。

截图时临时隐藏其他 body 子元素，只保留背景，避免 body 内容被重复截入背景图。

生成 DOCX 时，背景图作为文档后方的浮动图片放在页面后面。

### 7.4 绝对定位装饰

绝对定位或固定元素不进入正文流。满足尺寸和页面范围限制的元素：

- 局部截图；
- 存储相对 body 内容区的坐标；
- 存储内容区的宽/高；
- 在 Word 中按比例缩放到内容区；
- 在页边距坐标系中作为浮动图片定位。

不在安全范围内的绝对定位元素被丢弃，避免错误装饰覆盖正文内容。

**祖先内装饰（`inParent`）**：如果装饰完全落在最近的定位祖先框内（横幅右侧的叶片图标、区块左上角的水印数字），分类器额外记录其相对该祖先的坐标和祖先宽/高。注意定位祖先必须手动沿父链查找——SVG 元素没有 `offsetParent`。生成侧当该祖先渲染为卡片时，装饰锚定到卡片单元格（`relativeFrom: column/paragraph`）并绘制在底纹之上（否则底层图片会被单元格底纹覆盖）；卡片扁平化时，锚定到扁平化输出开头的零高度锚点段落，顶部空白只压缩到仍能容纳装饰的高度。这类装饰不受"仅首页"限制；当没有卡片上下文可回退且超出页面锚定路径时，首页之后的装饰由
