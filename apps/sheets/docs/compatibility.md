# XLSX 兼容性契约

V1 的产品承诺是：

> 以高保真度打开、编辑和保存常见的 XLSX 工作簿。保留不支持的高级内容，或对其明确警告。

“能打开”是不够的。每个受支持的功能都必须通过无操作往返、编辑往返、结构验证、语义比较和 Excel 视觉审查。

## V1 支持的目标

- 标量值、日期、布尔值、错误、共享字符串和内联字符串。
- 已发布函数矩阵内的 A1 公式和跨工作表引用。
- 字体、填充、边框、对齐、数字格式、行高和列宽。
- 合并单元格、隐藏的行/列/工作表、冻结窗格、排序和筛选。
- 已发布子集中的条件格式和数据验证。
- 表格、定义名称、批注、超链接和图片。
- 已发布子集中的柱状图、条形图、折线图、面积图、饼图和散点图。
- 工作簿计算设置和缓存的公式值。

## 保留但不执行

- XLSM 包中的 VBA 项目。
- 外部工作簿链接和数据连接。
- Power Query、Power Pivot 和嵌入式数据模型。
- OLE 对象、ActiveX 控件、切片器和不受支持的图表扩展。
- 未知的供应商扩展和自定义 XML 部件。

任何无法保留这些部件的保存操作都必须失败关闭（fail closed）。它不得静默生成一个被削减的工作簿。

## V1 明确不支持

- 编辑或执行 VBA。
- 刷新 Power Query 或外部数据。
- 编辑 Power Pivot 模型、ActiveX、OLE 和表单控件。
- 在每种字体和打印机配置下像素级一致的打印布局。
- 保证与每个 Excel 私有扩展兼容。

## PoC 能力

当前 PoC 有意支持更窄的写入集合：

- 在流式外部工作簿中编辑、清除或添加单元格值和公式，保存回去（或另存为）时进行整文件 SHA-256 漂移检查；仅重写被编辑的工作表条目、`xl/styles.xml`（当样式更改时）和 `xl/workbook.xml`（强制重新计算标志），其他每个 ZIP 条目都验证为字节一致，否则保存失败关闭。单元格样式索引在编辑后保留；共享字符串单元格被重写为内联字符串；新行和单元格按 Schema 顺序插入。
- 对流式工作簿进行功能区样式编辑（粗体/斜体/下划线/删除线、字体族/大小、带完整取色器的任意字体/填充颜色、清除填充、带 13 种线型和边框颜色的逐边边框、对齐、换行、数字格式），以写时复制方式写入 `styles.xml`：从每个单元格的原始格式派生出去重后的新 cellXfs/fonts/fills/borders（未触及的边框边和对角线属性原样保留），内置数字格式 id 映射，自定义 id 从 164 开始分配。仅样式编辑使单元格内容保持字节一致。图案填充编辑有意不在范围内（没有对应的编辑器模型）。
- 重命名工作表（演示工作簿 DSL 流程）。
- 保留未触及 ZIP 条目的未压缩内容哈希。

- 在每种加载模式下插入或删除行/列以及合并/取消合并单元格——包括流式大型工作簿：视口读取通过日志化操作流在屏幕坐标 ↔ 文件坐标之间转换，操作在保存时按顺序重放，重新编号行/单元格并移动同一工作表中的公式引用（绝对和相对、带 Excel 钳制/扩展语义的范围、整行/整列引用、共享/数组公式锚点、CF/DV 规则公式）、合并、dimension、列宽、超链接、autoFilter 以及 CF/DV 范围。其他工作表公式、工作簿定义名称和图表系列（`c:f`）中对被编辑工作表的限定引用随之移动。过期的 calcChain 连同其内容类型和关系一起被丢弃。过大而无法重写的条目（>256MB）通过 XML 文本扫描流式处理：如果它们无法引用被编辑的工作表，则原样原始复制；否则保存失败关闭。当引用指向已删除的范围，或当被编辑的工作表带有表格或绘图时，保存也会失败关闭。

- 图表编辑（也适用于流式大型文件）：标题文本（保留首次运行的样式，或插入并重置 `autoTitleDeleted`）、在柱状图/条形图/折线图/面积图族内的图表类型转换（保留系列和轴引用，剥离跨类型系列选项）以及系列纯色（填充 + 线条）。饼图/散点图/组合图仅接受标题和颜色编辑。不支持的形状失败关闭。

- 工作表复制（完全加载的工作簿，或本次会话中创建的工作表）：选项卡上下文菜单的“复制”记录一个 `duplicate-sheet` 操作；保存时原样克隆源工作表部件（剥离 tabSelected），重放复制时捕获的源工作表未保存编辑，并追加副本自身的编辑。超链接关系随部件一起克隆；printerSettings 关系被丢弃（连同其 `pageSetup` r:id）。带有绘图、表格、批注或数据透视表的源，以及带有工作表作用域定义名称的源，失败关闭。副本的副本链解析到原始文件部件。

- 工作表管理（也适用于流式大型文件）：重命名——workbook.xml 条目以及每个限定引用（其他工作表的 `<f>`/CF/DV 公式、定义名称主体、图表 `c:f` 系列、内部超链接锚点）一起重写，并遵循新名称的 Excel 引用规则；添加——一个空白工作表部件及其内容类型覆盖和关系，插入到其屏幕选项卡位置，立即可编辑（值、样式和行/列操作记录到新部件中）；删除——该部件、其关系、其内容类型覆盖及其关系被丢弃，连同该工作表拥有的附属部件（绘图及其图像和图表、旧版 VML、批注、线程化批注、表格——每个都有自己的关系和内容类型覆盖；仍从幸存工作表的绘图引用的媒体被保留），作用域为该工作表的定义名称随之消亡，幸存的 `localSheetId` 作用域和活动选项卡重新编号。当任何幸存公式、图表或定义名称引用该工作表（包括对该工作表表格的结构化引用）、当该工作表带有数据透视表或无法识别的部件，或当不会留下任何可见工作表时，删除失败关闭。添加或删除工作表会使 calcChain 失效，将其丢弃以供 Excel 重建。

- 整行移动（拖动所选行的表头；仅限完全加载的工作表）：记录为建模为两个相邻行块交换位置的移动操作——一个双射，因此不会删除任何内容，也不会有任何引用变成 #REF!。保存时重新定位 `<row>` 元素本身（高度、隐藏标志、大纲级别和单元格样式随其行一起移动，sheetData 按升序重新排序），并通过交换重映射每个引用：同一工作表和跨工作表公式、定义名称、图表系列、合并、CF/DV 范围、超链接、绘图锚点（按 from/to 对判断）以及表格引用。完全位于移动块内的范围随之移动；块外或跨越块的范围保持不动；任何部分重叠的内容都会使保存失败关闭（包括共享/数组公式锚点、表头/汇总行以及撕裂的绘图锚点）。撤销以反向移动的形式到达，并取消日志对。列移动仍被阻止。
- 行高、列宽、自动调整重置以及隐藏的行/列（每种加载模式，包括带表格或图表的工作表——尺寸调整不移动任何内容）：记录为有序的轴属性操作，并重放到行 `ht`/`customHeight`/`hidden` 属性和保留拆分的 `<cols>` 重写中。清除格式/全部清除将单元格重置为默认 xf（`s="0"`）；清除后应用的格式从默认样式派生。

- 大纲分组（数据 → 组合/取消组合/隐藏明细数据/显示明细数据，每种加载模式）：行/列 `outlineLevel` 和 `collapsed` 由 sidecar 解析（行随范围读取流式处理，列随工作表元数据），并按工作表跟踪；组合/取消组合将选区中每个连续的同级运行移动 ±1（钳制在 0-7），并记录声明式 `set-rows/cols-outline` 操作，重放到行属性和保留拆分的 `<cols>` 重写中，并重新计算 `sheetFormatPr` 的 `outlineLevelRow`/`outlineLevelCol`。隐藏/显示明细数据通过正常的隐藏行流水线隐藏或显示所选明细范围，并切换后续汇总行上的 `collapsed`（Excel 的 summaryBelow/Right 默认值）。级别编辑直接记录（Univer 没有大纲模型），因此不可撤销，也不渲染 +/- 装订线——折叠的组显示为隐藏的行/列。

- 通过 Univer 的规则面板创建/编辑/删除条件格式规则，以声明式保存：被编辑工作表的每个 `<conditionalFormatting>` 节都从实时规则模型重写（优先级重新编号），高亮样式作为新 dxfs 内部化。支持：cellIs、文本运算符（带 Excel 兼容的公式主体）、空白/错误、重复/唯一、前 10 项、高于/低于平均值、表达式、色阶、数据条以及 OOXML 图标集。失败关闭：x14 扩展规则、日期发生规则、Univer 专有图标集、混合/自定义图标顺序。在工作表上编辑 CF 会通过模型重新序列化其未触及的规则——读取器未映射的 dxf 属性（边框、数字格式）在该工作表上被丢弃。

- 通过 Univer 的验证面板创建/编辑/删除数据验证规则，以声明式保存：被编辑工作表的 `<dataValidations>` 节从实时规则模型重写。读取器解析完整属性集（allowBlank、showDropDown、提示、错误样式/标题/文本），并将规则原样安装到 Univer 中——安装保真度即保存保真度——包括跨工作表列表引用和 `time` 规则（它们在没有验证器的情况下渲染，但字节精确往返）。映射是双射的：OOXML `none`↔Univer `any`、列表字面量 `"a,b"`↔`a,b`、引用/自定义公式获得/失去前导 `=`、面板编辑的日期/时间字符串变为 Excel 序列号，以及 OOXML 反转的 `showDropDown` 标志被规范化。失败关闭：x14 扩展验证和 Univer 专有多选列表规则。复选框规则（插入 → 复选框）在保存时降级为双值 OOXML 列表——默认的 1/0 对保存为 `"1,0"`，并在重新打开时恢复为复选框规则；Excel 显示一个普通的 1/0 下拉验证。编辑被门控，直到工作表自身的文件规则被安装（索引完成），因此声明式重写永远不会丢弃模型未见过的规则。

- 定义名称（名称管理器）：添加、编辑和删除工作簿作用域和工作表作用域的名称，通过声明式重写 `<definedNames>` 保存。`_xlnm.*` 内置项、隐藏名称以及引擎无法建模的名称按字节原样保留；名称规则经过验证（失败关闭）；定义名称编辑不能与行/列或工作表结构更改在同一遍中保存。

- 工作表保护切换（审阅选项卡）：保护写入 Excel 的默认 `<sheetProtection sheet="1" objects="1" scenarios="1"/>`（无密码）；取消保护移除该元素，并在工作表受密码保护时失败关闭。文件的保护状态由索引线程解析，并在索引后在按钮上回显。编辑器本身不强制执行保护——结合“设置单元格格式”的锁定/隐藏标志，强制执行发生在 Excel 中。

- 在任意单元格添加/编辑/删除超链接：外部目标写入 `<hyperlink r:id>` 加上 TargetMode="External" 关系（rels 部件按需创建，孤立的 rels 被收集）；内部 `Sheet!A1` 锚点写入 `location`。每个单元格一个链接；未触及链接上的工具提示/显示属性被保留。

- “设置单元格格式”对话框（⌘1）涵盖数字格式、对齐（水平包括两端对齐/分散对齐、垂直、换行、方向预设、缩进）、字体、边框、填充和单元格保护标志。缩进渲染为左侧单元格内边距（`pd.l`，每级 `INDENT_STEP_PX` 像素），可撤销，通过正常的 set-range-values 通道记录，保存到 xf 的 `<alignment indent>`，并从打开的文件读回。锁定/隐藏保护仍没有 Univer 模型：它直接记录并保存到 `<protection>`（省略默认值），但不在屏幕上渲染、不可撤销，也不由编辑器强制执行——它在 Excel 保护工作表时生效。

- 文本旋转（OOXML `textRotation` 0-180 和 255 堆叠）和双下划线（`<u val="double"/>`）通过相同的写时复制样式流水线。分列按逗号/分号/空格/制表符拆分单个选定的列（完全加载的工作簿；拆分的单元格写入和任何插入的列搭乘现有日志）。文件侧文本旋转往返：导入的旋转通过相同的映射渲染。

- 表格创建（在导入的工作簿上使用 AI `add_table`）：渲染为原生 Univer 表格（带状样式、筛选下拉菜单），并保存为全新的 `xl/tables/tableN.xml` 部件，带有工作表 `<tableParts>` 挂接、关系和内容类型覆盖。列名在应用时从屏幕表头行捕获，按 Excel 规则清理（空白 → ColumnN，重复项加后缀）并写回单元格，使部件和工作表一致。保存时失败关闭：表格/定义名称冲突、与现有表格/工作表自动筛选/合并单元格重叠、空白或重复的列名，以及表格所在工作表在同一保存中的行/列移动。编辑或删除文件中已有的表格、公式中的结构化引用以及渲染预先存在的表格样式仍不受支持。

- 数据透视表创建（在导入的工作簿上使用 AI `add_pivot`）：应用在渲染器中聚合源范围（求和/计数/平均值/最大值/最小值；一个行字段，可选列字段），并将网格——包括总计——作为普通日志写入烘焙到目标单元格中。保存添加原生数据透视表部件：一个带有 `refreshOnLoad="1"` 和零记录的 pivotCacheDefinition、一个空的 pivotCacheRecords，以及一个 pivotTableDefinition，其 `<location>` 覆盖烘焙的网格，通过工作簿 `<pivotCaches>`、工作簿/工作表/数据透视表 rels 和内容类型覆盖连接。Excel（以及 LibreOffice——往返已验证）在打开时从源重建缓存，将烘焙的网格变为实时数据透视表。保存时失败关闭：重复的数据透视表名称、源之外的字段索引，以及涉及工作表上的同一保存行/列移动或工作表管理。重新打开保存的文件会保护数据透视表输出区域免受编辑（现有行为）。

- 排序和筛选（仅限完全加载的工作簿）：排序重新排序模型并将受影响的范围记录为单元格编辑；筛选交互（创建/编辑/清除）将实时筛选快照到 `<autoFilter>`/`<filterColumn>` XML——值列表、空白标志和自定义条件（六个 OOXML 运算符加上通配符值）——被筛掉的行在筛选的行跨度内声明式地写为 `hidden="1"`。颜色筛选没有 XLSX 映射并中止保存；Excel 表格拥有的筛选被阻止编辑（其状态存在于表格部件中）。

范围移动不可保存，并在导入的工作簿上被主动阻止。文件中已有的图像和形状可以移动、调整大小和删除：拖动/✕ 编辑器针对视觉对象的 (drawingPath, anchor index) 定位器记录一次外科手术式编辑，保存时仅重写或移除该 `<xdr:*CellAnchor>` 元素（孤立的图像 rels/媒体保留——无害，保留字节）。删除图表会级联：锚点、其绘图关系、图表部件及其自身 rels 以及内容类型覆盖全部消失（图表拥有的颜色/样式部件作为无害的未引用条目保留）；当另一个锚点仍引用该图表时删除失败关闭，非图表图形框架保持只读。绝对锚点在移动时失败关闭。图表系列数据范围可编辑（内联 ✎ 编辑器和 AI `edit_chart`）：从工作表读取新的单行/列范围（流式文件通过 sidecar 获取并叠加日志编辑），烘焙到系列缓存中，并保存为重写的 `<c:f>` + `numCache`/`strCache`，保留原始 `formatCode`；散点图（xVal/yVal）保持只读。保存通过 Rust sidecar 流式处理：未触及的条目是原始复制的压缩字节（由 CRC 清单验证），因此总工作簿大小无上限——只有被修补的单个条目必须 ≤256MB 未压缩；对更大条目的编辑失败关闭。

外部 XLSX 文件还额外支持工作表尺寸、标量值、共享字符串和内联字符串、布尔值、公式、缓存公式值和源样式索引的只读流式处理。字体（包括下划线和删除线）、填充、边框、对齐（包括自动换行）以及完整的 ECMA-376 内置数字格式表被映射到工作表渲染器中。RGB、索引调色板和主题+色调颜色在 sidecar 中解析（theme1.xml clrScheme 带 Excel 索引交换和 HSL 亮度色调）。合并单元格、冻结窗格、隐藏的行和列、自定义行高、隐藏的工作表、工作表选项卡颜色、每工作表网格线可见性和默认列宽被应用到渲染的工作表。共享字符串中的富文本运行渲染为逐运行样式的单元格文本。超链接单元格（外部和内部）以链接样式渲染。条件格式——cellIs 运算符、文本运算符、空白、重复/唯一、前 10 项、表达式、色阶和数据条——由 Univer 条件格式引擎从解析的规则和 dxf 样式实时评估。工作表选项卡和大型稀疏范围无需创建完整的 JavaScript 工作簿快照即可显示。

双单元格绘图锚点、嵌入的 PNG/JPEG/GIF/BMP/SVG 图像以及缓存的柱状图、水平条形图、折线图、面积图、散点图、饼图、圆环图和条形-折线组合图（带多系列分组、系列图例、带网格线的 y 轴刻度以及小系列上的值标签）显示在 Univer 的浮动对象层上。基本的不支持形状会收到可见的占位符，而不是静默消失。

此里程碑不声称原生 Excel 图表保真度。特别是对于流式外部工作簿，图表主题、次坐标轴、趋势线、3D 效果、复杂 DrawingML 形状、图标集
