# 架构

## 信任边界

```text
渲染进程（React 电子表格外壳 + Univer）
  -> 类型化预加载桥接
  -> 经过验证的 Electron IPC
  -> Rust XLSX 边车进程
  -> 临时行块索引
  -> 写时复制 OOXML 网关

渲染进程
  -> 上下文提取器
  -> 本地隐私策略
  -> 云端规划器
  -> 不受信任的命令 DSL
  -> 本地验证与试运行
  -> 用户审批
  -> 原子提交与审计
```

文档核心是唯一的工作簿写入者。渲染进程无法访问磁盘、模型凭据或子进程。云端模型无法调用原生能力或提交文件。

Electron 主进程负责 XLSX 边车进程的生命周期。渲染进程接收一个不透明的会话 ID，只能请求经过验证且大小受限的工作表范围。在此流式路径验证期间，外部工作簿为只读。

## 渲染进程组成

React 负责桌面标题栏、Ribbon 导航、AI 面板、异步状态和文件元数据。Univer 负责公式栏、工作表画布、工作表标签、选区、滚动和缩放控件。

AI 面板是可折叠的，与工作表平级，而非永久覆盖层。折叠它会扩展工作表列宽，而不会重建 Univer 运行时或工作簿会话。

## 样式与视觉对象

边车进程解析 `styles.xml` 单元格格式，并在每个流式单元格中携带源样式索引。渲染进程将字体、填充、对齐和数字格式转换为 Univer 单元格样式数据。

工作表关系文件用于定位绘图部件，而无需解析工作表主体。绘图锚点随后解析图表和图片关系。图表使用其 OOXML 缓存类别和值，并渲染为 Apache 许可的 Univer 浮动 DOM 组件；这避免了对许可受限的 Univer Pro 图表包的依赖。嵌入图片数据仅在其锚定对象被安装时加载，通过经过验证的 20MB 媒体端点。浮动对象会针对活动工作表和视口重新安装，因此屏幕外的绘图不会创建无界的 DOM。

## 大型工作簿读取

边车进程读取 ZIP 元数据、工作簿关系、工作表尺寸和共享字符串，而不构建 JavaScript 工作簿快照。对某个工作表的首次范围请求时，它将工作表 XML 一次性流式写入临时 256 行块。范围请求只需等待所需的块，解析在后台继续进行。

Univer 以工作表尺寸和空稀疏单元格数据启动。滚动和活动工作表事件请求可见范围加上缓冲区。在安装另一个窗口之前，先前的范围和格式会被清除，因此渲染进程内存不会随工作簿总大小增长。视觉发现仅读取关系、绘图、图表、样式和媒体元数据部件；它从不为大型工作表构建 DOM。

## 工作簿状态

每个文档最终拥有：

1. 原始 XLSX 包。
2. 规范化编辑器快照。
3. 带修订的操作日志。

PoC 实现了规范化快照和内存日志。OOXML 网关独立运行，以证明未触及的包条目在外科手术式单元格编辑后仍然保留。

## 适配器边界

产品代码依赖 `WorkbookAdapter`，而非 Univer API。该适配器暴露：

- `getSnapshot`
- `plan`
- `apply`
- `undo`

这样，即使编辑器更换，AI 规划、事务安全和审计行为仍可替换。

## XLSX 保留

网关：

- 验证 ZIP 路径安全性和条目数量；
- 限制总解压数据量；
- 通过 SHA-256 清点每个解压条目；
- 通过工作簿关系解析工作表；
- 仅重写目标工作表或工作簿元数据；
- 拒绝未知的工作表映射和过期的文件哈希；
- 通过临时同级文件和原子重命名写入。

当前网关不声称完全兼容 OOXML。其契约是未列出的条目保持相同的未压缩字节。

## 生产环境差距

- 持久化 SQLite 事务和审计日志。
- 完整的 XLSX 到编辑器导入模型。
- 高保真边框、主题颜色、条件格式、可编辑绘图和可编辑原生图表。
- 表格、名称、验证、合并单元格、筛选器和冻结窗格。
- 公式计算和差异化 Excel 验证。
- 本地隐私分类器和云端模型网关。
- 签名更新、崩溃恢复、遥测和企业控制。
