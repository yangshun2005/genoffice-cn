# genoffice — 从终端使用 GenOffice

`genoffice` 随 GenOffice 一起安装。先运行 `genoffice --version`。如果找不到该命令，GenOffice 每次启动时会将启动器目录写入 `~/.genoffice/launcher`（Windows：`%USERPROFILE%\.genoffice\launcher`）：读取那一行，然后在 bash 中运行 `"<dir>/genoffice"`，或在 PowerShell / cmd 中运行 `"<dir>\genoffice.cmd"`，加引号，替代下文的 `genoffice`。该文件缺失时的默认位置：macOS `/Applications/GenOffice.app/Contents/Resources/cli`，Windows `%LOCALAPPDATA%\Programs\GenOffice\resources\cli`，Linux `/opt/GenOffice/resources/cli`。每个命令都在应用自有引擎上无头运行；只有 `search`、`image` 和 `media` 会将数据发送到本机之外，发送到 GenOffice 中配置的提供商。

当程序读取输出时，始终添加 `--json`：stdout 上一个 JSON 对象，`{ "status": "ok" | "partial", "command", "summary", "output_path"?, "warnings"?, "detail"? }`（`partial`：带 `--best-effort` / `--stop-on-error` 的 `apply` 写入了文件但丢失了操作）或 `{ "status": "error", "code", "error", "message", "suggestion"?, "detail"? }`。退出码：`0` 正常，`1` 用法错误或操作被拒绝，`2` 文件未找到 / 输出已存在 / 文件在 GenOffice 中打开，`3` 转换失败，`4` 应用不可用。`error` 是机器可读的原因（见"命令失败时"下的表格），`suggestion` 是一句话的下一步，包括当命令、选项、操作名、元素 id 或工作表名仅差一个拼写错误时的 `did you mean "…"?`。`detail` 以字段形式携带事实（`failures[]` 含 `index`、`op`、`error`、`reason`、`valid_range`、`available`、`supported`、`usage`；`sheets`、`options`、`commands`）；永远不要解析 `message`。
